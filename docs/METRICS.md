# 指标口径与验证边界

全部时间使用 Asia/Shanghai；本地模拟统一存储无时区时间，不混入其他时区。生产环境应采用 UTC 存储、展示层转换。

## 两条时间轴

- `event_at`：反馈在业务侧实际发生的时间。
- `arrived_at`：反馈到达监控系统的时间。
- `submitted_at`：订单提交事件时间。它决定订单所属的业务观察窗口。
- `window_end`：观察窗口结束时间。
- `as_of`：目前已知道哪些消息的截止时间。

只有 `arrived_at <= as_of` 的反馈进入原始已知表。对每笔订单，在已到达反馈中选取 `event_at <= window_end` 的最新累计状态。回补不能把窗口之后发生的成交提前计入历史窗口。

## 分母和分子

订单提交范围为 `[window_end − 300秒, window_end − 60秒]`，两端均包含。即五分钟提交窗口中，剔除尚未满一分钟的订单。每条订单只出现一次。

| 指标 | 定义 | 注意事项 |
| --- | --- | --- |
| 成熟订单数 | 有效且落入上述范围的订单数 | 不等于最近五分钟全部订单 |
| 完全成交占比 | 最新已知状态为 FILLED 的订单数 / 成熟订单数 | 按笔数，不按金额；FILLED 数量必须等于订单数量 |
| 拒单占比 | 最新已知状态为 REJECTED 的订单数 / 成熟订单数 | 不是“收到反馈的订单数”作分母 |
| 反馈缺失率 | 没有符合截止条件的有效反馈的订单数 / 成熟订单数 | 可能是缺失、延迟或业务未处理，不能单独认定根因 |
| 部分成交 | 最新状态为 PARTIAL 的订单数 | 不算完全成交，不算缺失；反馈数量是累计值，不能相加 |
| 到达延迟 P95 | 各订单最新已到达有效反馈的 arrived_at − event_at 的连续分位数 | 只覆盖已到达反馈；未知延迟不填零 |

当前生成器只产生 FILLED / REJECTED；引擎另支持 PARTIAL，已通过手算样本测试。没有反馈但已提交的订单始终保留在分母，防止仅以成功到达记录统计造成幸存偏差。

空样本的比率和 P95 为缺失值，显示“—”。不同通道合计时重新计算总分子 / 总分母；P95 必须合并底层样本计算，不能平均通道 P95。

## 基线与告警

使用前一日、种子 2025 的独立正常模拟数据，形成 20 个不重叠窗口，分别统计汇总与各通道的均值、样本标准差。

- 成交下界：`mean − max(3 × std, 0.08)`，下限为零。
- 拒单上界：`mean + max(3 × std, 0.08)`，上限为一。
- 订单少于 30 笔：样本不足，停止比例告警。
- 反馈缺失率大于 5%：优先数据链路核查；业务问题仍可能并存。
- 反馈基本完整且成交或拒单比例越界：业务异常待核查。
- 比例恢复但 P95 大于 10 秒：提示迟到数据已回补，仍需链路调查。

上述为可解释的演示控制规则，**不是显著性检验，也不是置信区间**。真实数据需考虑时段、通道规模、相关性、多重检验与阈值漂移。反馈缺失任何一笔都会让结果标“暂定”；只有超过配置比例才提升为数据链路告警。

## 数据治理规则

原始记录保留；事件编号相同且业务内容相同的重复消息保留最早到达一条。相同事件编号内容冲突的消息全部隔离，不猜测哪条正确。未知订单、无效状态、非法数量、时间顺序错误进入隔离表。重复订单编号目前整组排除，属于原型的保守策略，生产系统需根据订单版本建模。

`quality` 是截至回放时刻的累计接入质量；业务 KPI 是当前观察窗口。二者时间范围不同，页面与证据中明确标注。无通道归属的隔离记录仅在“全部”原始表中显示，并单独报告全局数量。

## 可证伪与限制

“反馈未到齐”是观察事实；“由消息链路延迟导致”只是候选解释。若同一窗口回补后异常仍在，应继续查业务原因。行情、通道日志、拒单原因码和真实上游对账源未接入，因此不能确定真实根因。

场景评估单位是每个种子的一次故障结束窗口，不把相邻重叠窗口算作大量独立样本。预设故障集上的效果不代表生产误报率。
